Direct Word object-model checks

Formatting checks use Word-resolved bold and italic, including inherited styling, at ordered literal paragraph offsets. Table checks cover top-level table text. Hyperlink checks compare visible link text; captured destinations are retained but are not scored here. Resolved formatting has a three-second capture budget per document in this run; incomplete captures are unscored for every parser. This subset favors simpler documents and is not a full-corpus formatting score. Other metrics retain their own reference coverage.

Why exact feature scores can be low

Explicit bold and italic below compare formatted characters at aligned text positions. XML run boundaries do not affect this check. It measures positive explicit-formatting recall only: inherited styles are outside this reference, so it cannot establish precision or complete formatting correctness.

Formatting includes body textboxes and ignores whitespace. Header/footer paragraph presence preserves duplicate counts but ignores ordering and section placement. Textbox literal retention permits added characters and does not validate positioning or extra output. These diagnostics supplement the exact scores below.

What needs a stronger reference?
  • Resolved formatting: compare bold and italic flags at character positions, including unformatted text, to measure both precision and recall. The completed Word-resolved subset above is narrower than the explicit-formatting diagnostic.
  • Hyperlinks: include field-generated links, distinguish textboxes from the main story, and score destination and position. Word’s hyperlink collection can omit valid field links; adjacent links can also merge in the adapter. Microsoft documents the PAGEREF hyperlink switch.
  • Tables and textboxes: account for symbol glyphs and match structural positions. Literal text retention does not establish correct cell geometry or absence of extra content.
  • Headers and footers: match section and header/footer role before checking order within each part.

Word-saved structure checks
Word saves a Flat OPC package after opening the document and accepting revisions on a disposable copy. The independent XML extractor reads that export. These checks still depend on the extractor’s interpretation: image and equation counts are proxies, explicit formatting is segmentation-sensitive, and raw spans describe stored structure rather than visual geometry.


Original package image payloads
This separate source-byte check matches native image occurrences to original payload hashes one-to-one for all four parsers. It is not a Word rendering score, and is not mixed into the Word-derived metrics.


Reference and measurement provenance
Original inputs are SHA-256 verified. Captures retain Word version/build, source hash, exporter hashes, Word’s JSON output, and a compressed Flat OPC export. Macros and external-link updates are disabled. Captured references and timed parser jobs run in separate phases. The current package is extend-docx; historical records retain docx-core as its engine identifier. This benchmark does not change parser behavior.
