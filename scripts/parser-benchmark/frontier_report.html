What changed, and what the source investigations showed

Complete semantics in a smaller representation

  • Resolved formatting can be shared with copy-on-write mutation, avoiding repeated copies between runs and import provenance.
  • Boxed uncommon paragraph children reduce the space occupied by ordinary text runs.
  • Typed structured-block details retain eagerly resolved values without constructing a generic JSON tree during parsing.
  • XML hot paths retain compatibility fallbacks and full source preservation.

    Rust API migration: SharedTextStyle, boxed image/form-field children, and typed BlockDetails change Rust construction types. Serialized model/block output is protected by the full differential audit. Rust callers that construct those values need to adapt.

    Source-backed mechanisms, with bounded conclusions

    office_oxide uses shared effective formatting and compact model variants. Its body and property parsers consume a shared XML reader. undoc also reconstructs and reparses XML fragments, so its speed cannot be explained by “single pass” alone.

    Static REA analysis found token/state parsing, pointer-and-length token access, a small allocation arena, namespace-pointer caching, and integer token lookup in libraries shipped with Word.

    Those are observed library mechanisms. The exact Word DOCX import route, editable-model allocation strategy, and runtime latency remain unresolved. The investigation does not prove that Word is optimal or that a particular import uses every inspected mechanism.

    Actual gaps and unresolved behavior

    • Some font-specific symbols still produce private-use characters instead of meaningful Unicode text.
    • Resolved table geometry uses heuristics; raw column-span equality cannot establish Word-equivalent wrapping or pagination.
    • Embedded content and diagrams include source-preserved paths without complete semantic interpretation.
    • Equation and composite-graphic presence does not prove rendering fidelity.

    What the existing oracle does not establish

    • Exact hyperlink destinations and styled character ranges.
    • All source-reference ranges, section inheritance, field states, and tracked-change identities.
    • Word-identical layout or a broad legacy DOC guarantee from two inputs.
    • Universal accuracy beyond the local corpus and differential cases.

    The Word-oracle checks exercise the reference and comparison harness. They are not an equal number of documents rendered and compared against Word. Full-output parity proves no change from the baseline under its declared normalization; it does not prove that the baseline is universally correct.

    The full native audit compares canonical hashes and value/event counts for every model and structured-block field, including source XML and binary payloads. Only JSON object-key order and paragraph/table style-definition order are normalized. All other arrays retain their order.
