Word formats: parsing, speed, and extraction

Actual binary formats are detected from content. Format variants are reported separately; generated variants are compatibility checks, not independent real-world corpora.

Input formats and MIME types

Content extraction only. Macros are not executed. The macro-enabled variants contain no VBA project. Template instantiation and lossless template or macro round trips are outside this benchmark. Encrypted inputs and pre-Word-97 binary formats are unsupported; RTF, ODT/OTT, HTML/MHTML, Flat OPC XML, PDF, XLS and PPT need other parsers.

Ordered text and precision

The original macro 5-gram score remains above. Micro F1 pools character grams. Ordered F1 uses exact longest-common-subsequence character matching; paragraph order is also checked. Both ignore whitespace and soft breaks. These remain extraction measures, not visual layout scores.

Feature cells show precision / recall / F1 for the declared unit. Textboxes must appear in a textbox. Story text uses ordered character matching. Image and equation counts are proxies; they do not prove payload identity or positioning. Explicit formatting and hyperlink anchors remain sensitive to segmentation and reference conversion.

    Method and limitations

    Binary .doc inputs are existing local documents. .dot inputs are LibreOffice-generated templates from those documents, independently reopened by LibreOffice for reference extraction. DOCX inputs include six paired fixtures plus six inputs spread by file size. DOTX, DOCM, and DOTM are controlled package variants with the main content type changed; they preserve source content and contain no VBA. Results for those formats are correlated.

    All parsers use the same optimized release executable and pinned comparison versions. extend-docx constructs its complete model and structured blocks; competitors construct their native model or IR. The harness passes DOC/DOCX families explicitly where required, so this measures byte parsing, not filename-extension routing.

    Input and engine order are randomized with a saved seed. Multiple warm samples per input; each averages 1–20 parses. First-parse measurements and raw samples are retained. This is a shared development machine, not an isolated performance lab. Small cohorts and differing output completeness limit speed comparisons.
